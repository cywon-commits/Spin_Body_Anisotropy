### 3.1 KT: Hasenbusch (2005) 유한 크기 값과 Weber–Minnhagen
β_KT = 1.1199에서의 βΥ(L)를 Hasenbusch 표 1(각 ±0.00007)과 비교했다.

| 모형 | L = 16 | L = 32 | L = 64 | WM T_KT/J | 판정 |
| --- | --- | --- | --- | --- | --- |
| 참값 (Hasenbusch) | 0.72536 | 0.70883 | 0.69785 | 0.8929 | |
| 순수 XY (J₂ = 1) | 0.72539(26), z = 0.1 | 0.70870(41), z = −0.3 | 0.69716(36), z = −1.9 | 0.8906(2) | 통과 |
| r = 0 (σ–φ 분리, 클러스터 3종) | 0.72541(29), z = 0.2 | 0.70919(30), z = 1.2 | 0.69774(33), z = −0.3 | 0.8909(2) | 통과 |
| J₂ = 0 (σ–ψ 분리, J₄ = 4·128/81) | 0.72623(34), z = 2.5 | 0.70870(40), z = −0.3 | 0.69720(38), z = −1.7 | 0.8903(3) | 통과 |

- **Υ = 2T/π 교차 T_L/J (순수 XY):** 0.9368 (16), 0.9278 (24), 0.9235 (32), 0.9186 (48), 0.9154 (64). L에 따라 단조 감소하며 T_KT로 다가간다.
- **판정 규칙 0.893 ± 0.01:** 세 모형 모두 통과했다.
- **주의 [수치확인]:** WM 값이 참값보다 약 0.0023 (0.25%) 낮다. 통계 오차로는 설명되지 않는 계통 편차다. Hasenbusch의 표 3에서도 상수 C가 L_min과 함께 커지므로 (0.67 → 1.43), C를 상수로 두는 WM 꼴은 L ≤ 64에서 이만큼 치우친다. L_min = 24로 맞춰도 0.8910(3)으로 거의 같다. 유한 크기 βΥ 자체는 참값과 오차 내에서 맞으므로 이 편차는 시뮬레이션이 아니라 맞춤 꼴에서 온다.
- **N1에 주는 의미 [추정]:** T ≈ 7 G에서 이 편차는 약 −0.017 G이고, 교차점 판정의 격차 ΔT(r)와 같은 크기일 수 있다. N1 보고서에는 WM 값과 함께 L ≥ 128을 포함한 맞춤, ξ_ψ/L 교차를 같이 보고하고, 이 편차를 계통 오차로 명시해야 한다. 판정 규칙 자체는 바꾸지 않는다.

## 4. 규칙·정의 변경과 그 이유 (결과 해석 전에 기록)
1. **4등분 검사의 오차 추정 방식 변경.** 처음에는 각 4분 구간 안의 5블록으로 오차를 냈고 기준을 |z| < 5로 두었다. 이 방식에서는 τ_int ≤ 2인 정상 실행 여러 개가 z = 4.9–5.5를 보였다. 원인은 오차 추정 자체다. 자유도 4의 t 분포는 꼬리가 두꺼운데, 실행 하나에서 비교를 최대 350번 하기 때문이다. 바꾼 방식은 다음과 같다.
   - 각 구간 평균을 나머지 세 구간 평균과 비교한다.
   - 오차는 전체 시계열 20블록 잭나이프에서 구한다 (구간 σ = 2σ_전체).
   - 기준은 비교 횟수에 대한 Bonferroni 보정(실행당 양측 p = 0.01, 약 3.9–4.2)으로 둔다.

   이 검사는 TASK의 사전 등록 판정 규칙이 아니라 CLAUDE.md 평형 규칙 3을 구현한 것이며, N1 데이터를 보기 전에 정했다.
2. **교환 수락률 정의.** 예비 계산은 수락 횟수를 스윕 수로 나눴는데, 각 쌍은 두 스윕에 한 번만 시도된다. 그래서 예비의 "0.15–0.21"은 시도당 약 0.30–0.42에 해당한다. 새 코드는 시도당 수락률을 기록한다. TASK N1의 "교환 수락 0.2–0.3" 목표가 어느 정의인지 의뢰자 확인이 필요하다. 예비 사다리(L = 64에서 26개)는 시도당 약 0.3–0.4이므로, 어느 정의로 보든 목표 범위 이상이다.
3. **왕복 횟수 정의.** 예비 계산은 아래→위 통과(반 왕복)를 셌다. 새 코드는 아래→위→아래 완전 왕복을 센다.

## 5. 남은 일과 N1 준비
- **커밋:** 코드는 아직 커밋하지 않았다. 커밋하면 N1 실행이 깨끗한 git 해시를 기록한다. 소스 해시는 패키지 전체(분석 모듈 포함)에 대해 계산하므로, 이후 분석 코드를 고친 지금은 값이 달라졌다. 시뮬레이션 파일(`rng`, `c3model`, `pt`, `run`)은 검증 실행 이후 바뀌지 않았다.
- **데이터:** `runs/n0/`의 HDF5(1.3 GB)는 git에서 제외된다. 요약 JSON만 저장소에 들어간다. N1 데이터(수 GB 예상)의 보관 위치는 의뢰자가 정해야 한다.
- **비용 재추정:** TASK N1의 비용 재추정 도구는 아직 없다. 측정값은 L = 64 1.9 ms, L = 128 7.5 ms /복제본·스윕(코어 1개)으로 TASK 추정의 약 절반이다. N1 전체는 약 35 코어-시간, 8코어로 반나절 정도로 예상된다 [추정].
- **사다리 설계:** N1 사다리는 configs/T1_runs.csv의 복제본 수를 그대로 쓰되, 시도당 수락률 기준으로 다시 확인할 것.
